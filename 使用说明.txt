一、这一版改了什么（针对前期两个问题）

  1. 文件夹内搜索的结果可以正常打开了
     旧版把「文件夹内搜索」结果单独放在 t.srch.items 里，且把绝对路径
     改写成了含反斜杠的相对显示名；而双击 / 右键处理器却一律从「当前
     目录的直接子项」里按名称查找、再用「当前目录 + 名称」拼路径。
     两套数据结构对不上，查找失败就直接 return，所以双击和右键都没反应；
     全局搜索走另一套逻辑，因此只有文件夹内搜索坏掉。

     新版规定：任何列表条目（目录列表 / 全盘搜索 / 文件夹内搜索 /
     暂存盘 / 剪贴板）都是同一种 FileEntry，绝对路径 path 是唯一身份；
     所有打开、右键、预览、定位、复制路径操作只认这个 path，
     绝不再按名称反查。搜索结果即使不在当前目录，也能直接打开。

  2. 不再压字
     · 列头与数据行共用同一套 CSS Grid 列定义（--cols）；
     · 所有文本容器 min-width:0 + overflow:hidden + ellipsis；
     · 搜索结果改为「主名称 + 相对路径副标题」两行，不再把超长路径
       硬塞进名称列；另设「位于」列显示父目录名；
     · 搜索条件条、地址栏、侧栏磁盘容量各自独立成行，按钮不参与挤压；
     · 窄窗格（三栏 / 四宫格）通过容器查询自动隐藏次要列，
       保证名称列始终有可读宽度；
     · 选中行只切换 class，不重建 DOM，双击 / 右键事件链不会被打断。

  3. 底层架构重写
     旧版是 1 个 385 KB 的 .pyw，前端 base64 内嵌、业务逻辑混在 HTTP
     路由里。新版拆成「领域层 / 服务层 / 传输层 / 界面层」四层：
       src/fmp/model.py       统一 FileEntry 模型（path 唯一身份）
       src/fmp/config.py      配置与会话原子持久化
       src/fmp/fs.py          目录、磁盘、属性、预览信息
       src/fmp/everything.py  Everything SDK / HTTP 适配
       src/fmp/search.py      统一搜索管线 + 本地索引兜底
       src/fmp/ops.py         文件操作 + 后台任务进度
       src/fmp/clipboard.py   系统剪贴板 CF_HDROP 双向互通
       src/fmp/server.py      静态资源、文件流与 /api 命令（127.0.0.1 + token）
       src/fmp/bridge.py      唯一命令路由 call(method, payload)
       src/main.py            启动、单实例、全局热键
       src/ui/                独立 HTML / CSS / ES 模块
     业务命令与二进制资源都在带 token 的本地服务里按路由分层。

  4. 启动不再受「桥注入时序」影响
     早期打包版把业务命令放在 pywebview 的 js_api 上，而 js_api 是
     异步注入的；若页面脚本先执行，会报
     「window.pywebview.api.call is not a function」并显示启动失败。
     本版改为本地 HTTP 命令通道（POST /api + 随机 token），
     不依赖 window.pywebview，启动竞态被彻底消除。

  5. 关闭不再卡死（未响应）
     早期版本在窗口 closing 事件里同步调用 evaluate_js 保存会话，
     WebView2 销毁阶段与 UI 线程互等，Windows 会弹出
     「…exe 未响应 / 关闭程序 / 等待程序响应」。本版去掉关闭时的
     跨线程 JS 调用，会话改由页面 pagehide 用 sendBeacon 异步保存；
     HTTP 请求线程改为 daemon、热键消息循环可退出，并加退出看门狗。
     实测连续两次点击关闭均在约 2 秒内干净退出。

二、快速开始

  ① 安装版：双击「文件管理多面手 1.1-Setup.exe」按向导安装。
     用户级安装（装到 %LOCALAPPDATA%\Programs，免管理员权限），
     可勾选桌面 / 开始菜单快捷方式；卸载走
     设置 → 应用 → 安装的应用（或安装目录内 Uninstall 快捷方式），
     个人数据保留在 %APPDATA%\FileManagerMulti\v1。
  ② 便携版：双击「文件管理多面手 1.1.exe」，无需安装、不写注册表。
  ③ 脚本版：双击「启动-文件管理多面手.bat」（需 Python 3.10+ 与
     pywebview；本机 Python 3.14 已就绪）。
  ④ 便携数据：在 exe 同目录放一个空的 portable.flag 文件，
     配置与数据会改存到同目录 data\ 下，可放 U 盘随身携带。

  运行环境：Windows 10 (1903+) / Windows 11 64 位，系统自带 WebView2。
  推荐组件：Everything（voidtools.com 官方免费软件），运行后即可全盘
  毫秒级搜索；未安装或未运行时自动退化为内置本地索引，功能不受影响。

三A、列宽与窗格宽度（方便看清长文件名）

  入口一：列头最右侧「列宽」按钮 → 打开设置面板，即时预览。
  入口二：工具栏「⋯ 更多」→「列宽与窗格宽度…」。
  入口三：顶部「设置」→「调整列宽与窗格宽度…」。

  1. 名称列
     · 默认「自动填满剩余宽度」，会随窗格大小变化。
     · 取消勾选后可指定固定宽度（180–1200 px）；其他列会按剩余
       空间等比收缩，名称列真的变宽，且不会把列挤出可视区。
     · 直接拖动「名称」列头右侧的分隔线也能调宽；
       双击该分隔线恢复自动宽度。
     · 大小 / 修改时间 / 类型的列头分隔线同样可拖动。

  2. 专注名称（一键）
     · 设置面板勾选「仅显示名称列」，或「⋯ 更多」→「仅显示名称列」：
       隐藏大小 / 时间 / 类型，名称占满整栏，适合浏览超长中文名。
     · 再点一次「恢复显示其他列」即可还原。

  3. 长名称两行显示
     · 设置面板勾选「文件名两行显示」：行高自动加高，
       长中文文件名分两行完整显示，不再被省略号截断。

  4. 左右分屏窗格宽度
     · 拖动两个窗格中间的分隔条即可改变左右比例（25%–75%），
       双击分隔条恢复均分；设置面板里也有「左窗格占比」滑块。

  所有设置即时生效并自动记忆（写入 config.json），下次启动保持。

三B、把文件拖出到资源管理器 / 云盘（1.1 新增）

  以前在网页内核里做的拖拽只在窗口内部有效，拖到桌面、资源管理器或
  云盘客户端时对方拿不到文件。现在改为由程序自身发起系统级拖放
  （OLE DoDragDrop + CF_HDROP），与资源管理器行为一致。

  1. 怎么拖出
     · 在文件列表里按住某一项（或已多选的任一项）向左/上拖出窗口，
       光标变成「复制」标记即已接管；拖到目标窗口松开即可。
     · 拖出过程中源窗格右下角显示「拖出 N 项」提示。
     · 支持跨目录多选（例如在搜索结果里选中不同文件夹的文件）一起拖。
     · 目标程序决定是复制还是移动；多数情况下松开即复制成功，
       状态栏会提示「已复制 N 项到外部程序」。

  2. 窗格之间仍然是内部拖拽
     · 同在程序内的两个窗格之间拖动：默认复制，按住 Shift 移动，
       走的是后台任务队列，带进度与可取消。

  3. 已知限制（系统层面，非本软件可绕过）
     · 目标程序必须接受 CF_HDROP 文件拖放。部分云盘客户端只认自己
       的上传按钮，对任何来源的拖放都不接收（可先用资源管理器试同一
       目标：若资源管理器也拖不进去，说明是对方限制）。
     · 从资源管理器把文件「拖进」本程序仍不可用（WebView2 安全限制），
       请改用 Ctrl+C / Ctrl+V，本软件的剪贴板与资源管理器完全互认。
     · 拖出时若目标程序以管理员权限运行、而本软件以普通权限运行，
       Windows 会拦截跨权限拖放（UIPI 限制）；反之亦然。

五、搜索服务说明（1.2 起内置搜索引擎，不需要单独安装 Everything）

  · 搜索内核随程序一起分发：安装包里已经带了 Everything 的内核
    （Everything.exe + Everything64.dll，MIT 许可，许可证随包附带）。
    内核完全隐形运行——不弹窗口、不占托盘、不开 HTTP/ETP 端口、
    也不检查更新，并且使用自己的一份私有配置
    （%APPDATA%\FileManagerMulti\v1\engine\Everything.ini），
    既不读也不改你自己安装的 Everything 的设置。

  · 三级来源，优先级明确：
      ① 机器上已装并运行的 Everything → 直接复用（状态栏显示
         「Everything SDK」）
      ② 没装 Everything → 自动释放并启动随包内核
         （状态栏显示「内置引擎」）
      ③ 内核都不可用 → 内置本地索引兜底（文件夹内搜索边遍历边出结果）

  · 首次启用只需点一次「是」：读 NTFS 的 MFT / USN 日志必须是管理员
    权限，Everything 官方的做法是安装一个约 1MB 的常驻索引服务。
    入口有两个：
      · 状态栏左下角「本地索引 · 点此启用全盘秒搜」
      · 设置 → 「内置引擎…」按钮
    授权后永久静默、随系统启动，之后再也不会弹 UAC；没授权时程序
    不会偷偷提权，只会如实显示「本地索引」。

  · 内核进程跟随管理器：退出程序时只结束「本程序启动的」内核，
    你自己开的 Everything 不受影响；不留常驻后台。索引靠 USN 日志
    增量维护，下次启动重读 MFT 一般 1–3 秒。
  · 首次启动会慢一些：内核要读全盘 MFT 建索引，实测 10–30 秒（盘大或多
    磁碟更久）。这段时间状态栏显示「内置引擎启动中…」，搜索结果由本地
    索引兜底、可能不完整；建好后就是毫秒级秒搜，之后每次启动只需读增量。

  · 状态栏左侧实时显示当前后端与内核版本；点击可重新连接，
    未启用时点击直接进入引擎管理弹窗（可看内核来源 / 服务状态，
    也可手动停止内核）。

  · Everything 1.5 alpha 支持拼音搜索；1.4 正式版不支持 pinyin: 语法。

  · 卸载安全：只有索引服务确实指向内置内核目录（说明是本程序装的）
    才会在卸载时一并移除，你自己安装的 Everything 服务一律不动。


五A、复制到云盘 / 微信等外部程序提示「无权限访问」

  先用一个实验定性：**用 Windows 自带资源管理器复制同一个文件到云盘，
  如果也报同样的错，就说明不是本软件的问题**，而是云盘客户端或云端目录
  的限制。本软件侧的检查方法：右键文件 →「检查外部程序可访问性」，
  会显示完整路径长度、文件属性、以及「任意进程可读 / 不可读」的判定。
  若显示「可读」，问题一定在云盘一侧。

  常见原因与处理（按可能性排序）：
    ① 目标是移动云盘「群组」空间里的文件夹（报「当前无权访问该文件夹，
       请检查文件权限后重试」）→ 这是云盘服务端的角色权限校验，
       与本机文件无关。群组成员分 7 种角色：管理员 / 编辑 / 上传+下载 /
       预览+上传 / 上传 / 下载 / 预览，其中「下载」「预览」角色没有上传权限；
       群组盘容量已满同样会报错。处理：请群管理员把角色调到「编辑」或
       「上传」及以上，或改传到自己的「文件」个人空间。
       快速定性：在同一个群组文件夹里用客户端自带的「上传」按钮试传同一个
       文件——同样报错即纯云端权限/容量问题，任何本地工具都无法绕过。
    ② 目标云端目录是群组中他人创建、当前账号只有查看权限 →
       换到自己的「我的文件」或请群主授予上传权限。
    ③ 源文件位于云盘自己的同步目录（如 D:\移动云盘同步盘）→
       先复制到桌面等普通文件夹，再从那里上传。
       注意：同步盘只自动上传「个人空间」内容，群组文件必须走客户端
       「上传」按钮或网页版。
    ④ 云盘客户端与文件管理器权限级别不一致（一个管理员、一个普通）→
       两者都以普通权限重新启动。
    ⑤ 客户端临时故障 → 重启客户端或改用网页版（yun.139.com）上传。

  推荐操作方式：在本软件选中文件按 Ctrl+C，再到云盘窗口按 Ctrl+V 粘贴，
  比直接拖拽稳定。本软件写的是标准系统剪贴板 CF_HDROP（另带
  FileNameW / Preferred DropEffect），并在写入前逐个校验路径可读、
  自动剥离内部长路径前缀；不可读时会明确提示而不是静默写入坏路径。

六、数据与卸载

  · 配置、收藏、标签、暂存盘、搜索历史保存在
    %APPDATA%\FileManagerMulti\v1\config.json，不联网、不上传。
    内置搜索引擎的内核与私有配置在 %APPDATA%\FileManagerMulti\v1\engine
    （约 2.3MB，删掉后下次启用会自动重新释放）。
  · 便携版：删除本文件夹与上述数据目录即可；若曾「启用全盘秒搜」，
    索引服务是系统级组件，需在「设置 → 内置引擎…」或卸载时一并移除
    （指向内置内核目录的服务才会被清，别人的 Everything 服务不动）。
  · 单实例运行：重复启动会唤起已有窗口。

九、版本号规则与升级方式

  1. 编号规则
     · 每更新一次（新增功能 / 修复 / 打磨），次版本 +1：1.0 → 1.1 → 1.2 …
     · 大版本重构或破坏性变更，主版本 +1 且次版本归零：1.x → 2.0
     · 版本号在窗口标题、程序文件名、安装向导、关于弹窗里都一致；
       「关于」（设置 → 关于）可随时查看当前版本。

  2. 升级会不会丢设置
     · 不会。个人数据按主版本归档在 %APPDATA%\FileManagerMulti\v1，
       1.0 / 1.1 / 1.2 共用同一份配置，收藏、标签、暂存盘、搜索历史、
       会话全部保留。
     · 从 1.0 升级时首次启动会自动把旧目录里的 config.json 搬过来。
     · 只有主版本变化（如 2.0）才会新建 v2 目录，届时同样自动迁移。

  3. 安装版如何升级
     · 直接运行新版 Setup.exe 即可就地升级，安装目录固定为
       %LOCALAPPDATA%\Programs\文件管理多面手，不会出现两份安装。
     · 安装程序会清除上一版的旧 exe、旧快捷方式、旧注册表卸载项与
       带版本号的旧安装目录，桌面不会堆一串不同版本的图标。
     · 「设置 → 应用」里始终只有一条记录，版本号显示当前版本。

  4. 便携版如何升级
     · 用新版 exe 替换旧版 exe 即可；也可两个版本并存各自运行，
       它们共用同一份用户配置。

  5. 每个版本改了什么
     · 见同目录「更新日志.txt」，按版本号倒序排列，最新在最上方。
