文件管理多面手 · 更新日志
============================================================

版本规则
  常规更新（新增功能 / 修复 / 打磨）   → 次版本 +1：1.0 → 1.1 → 1.2 …
  大版本重构、破坏性变更              → 主版本 +1 且次版本归零：1.x → 2.0
  发版方式：只改 src/fmp/version.py 里的 APP_VERSION，然后在项目根目录执行
            py src/tools/bump_version.py --minor     （或 --major / --set 1.3）
            再跑 py src/tools/bump_version.py --check 做一致性自检。
  发版铁律：每次更新都必须递增软件编号，不允许用同一个版本号覆盖已发布的包。
            构建脚本已接发版守卫（src/tools/release_guard.py）：源码改动过
            而 APP_VERSION 没变时直接拒绝出包，并列出改动的文件。
            仅本机验证可加 --allow-same-version，该产物不得对外发布。
            判定依据是 src 目录的源码指纹，改文档不影响版本号。
  命名规则（1.7 起）：版本号不写进文件名 / 快捷方式名 / 窗口标题，
            对外一律只叫「文件管理多面手」；序号放进软件包里——exe 属性里的
            文件版本、界面品牌处、关于、安装向导的版本对比。自检会拦下名字里
            带数字的产物（见 bump_version.py --check 第 3 项）。
            安装目录、注册表项、数据目录同样不含版本号，升级就地覆盖。

## 1.8  2026-11-16
------------------------------------------------------------

新增
  · 每套主题自带一副字色。生成时按「壁纸提亮 → 蒙层 → 半透明面板」三层
    合成出文字底下真正的底色，取最暗 2% / 中位 / 最亮 2% 三个亮度带分别
    校验；原字色不够就把墨往亮（浅字主题）或往暗（深字主题）逐级推，
    推到 86% 还不够才加厚面板。换主题即换字色，不再沿用上一套的墨。
  · 工作区不透明度滑杆加了「可读下限」：每套主题按自己的壁纸算出最低可读
    厚度（10%~90% 不等），拖到底会停在那一格，读数直接显示「75%（可读下限）」，
    不会出现「面板一透，字全糊在红底上」。
  · 次要信息（大小 / 修改时间）与提示文字各自验到 WCAG AA 的 3.6 / 2.8：
    以前是固定往面板底色混 30% / 52%，面板一透明这两档最先没影。
  · 文字光晕：壁纸是照片，字底下既有亮丝也有暗影，按最薄处的余量给一圈
    反向描边（浅字配暗影、深字配亮边），余量够时自动关掉，不糊笔画。

修复
  · 红色系主题（红日东方 / 赤诚）的字压在亮丝缎上几乎看不见：旧校验比的
    是「不透明面板」，而实际渲染是「半透明面板叠在壁纸上」，最亮那块只剩
    2.5:1。现在校验对象改成合成后的真实底色。
  · 顶栏 / 侧栏 / 状态栏比内容区薄一半（0.24 对 0.48），壁纸一亮就整片糊；
    改为按同一套门限单独算厚度，必要时抬到与内容区同厚。
  · 云海初醒、竹影清风、窑洞灯火、实事求是四套主题在半透明下其实也不达标
    （旧版报「无问题」），这次一并修好。

变更
  · 面板默认厚度按「舒适对比 5.6」反推，个别主题略加厚（窑洞灯火 0.48→0.68、
    实事求是 0.58、赤诚 0.50），换取滑杆的可用行程与更稳的默认观感。
  · 新增回归：tests/ink_test.py 67 项（字色关系与数据一致性）、
    tests/ink_check.mjs 32 项（浏览器截图逐像素量字底对比度）；
    皮肤专项 63 → 65 项。

## 1.5  2026-11-16
------------------------------------------------------------

新增
  · 皮肤面板新增「工作区不透明度」滑杆（0–100%）：调的是「工作面」
    （内容窗格、顶栏、侧栏、状态栏的底色厚度），而不是壁纸。
    100% = 该主题原来的厚度（外观与 1.4 一致），数值越小面板越透，
    主题图看得越清楚。设置随配置持久化（skin_surface）。
  · 模糊半径跟着厚度一起减：面板 100% 时 10px，调到 40% 只剩 4px。
    以前面板变薄而模糊不变，风景照样是一团糊，等于「调了也看不到图」。

修复
  · 「主题图能调透明度，但工作面不能调，看不到主题图」：滑杆原先做在
    壁纸层（body::before 的 opacity）上，面板始终 48% 厚 + 10px 模糊，
    把滑杆拉到 0 只是让背景彻底露白，中间的窗户纸没动。
    现在壁纸恒按原图显示，调的是它上面那层。
  · 面板透明度改用 CSS 变量 rgb(R G B / calc(...)) 表达。注意不能用
    老式 rgba(r,g,b,calc(...)) —— Chromium 会整条声明判非法，面板直接
    变全透明；也不要把变量取名 --pane-a / --pane-b，那两个键是 app.css
    里窗格宽度的分配比例，会被布局覆盖成 1.000fr。
  · 旧配置里的 skin_opacity（壁纸不透明度）不再生效，改为 skin_surface；
    老配置无需手工处理，读不到新键时按 100% 处理。

变更
  · 设置 → 界面皮肤的说明文字改为「工作面不透明度」，滑杆禁用条件仍为
    「默认皮肤」或「关闭壁纸」（没有壁纸时调它没有意义）。
  · 「恢复默认」一并把滑杆归 100%。

测试
  · 皮肤专项 61 → 63 项：新增「壁纸恒为原图」「滑杆 40% 时面板 alpha
    与模糊同步下降并复位」两类断言。

## 1.2  2026-11-13
------------------------------------------------------------

新增
  · 内置搜索引擎：Everything 内核随程序一起分发，用户不再需要单独安装
    Everything。内核（Everything.exe + Everything64.dll，MIT 许可，随包附带
    许可证）首次用到时自动释放到 %APPDATA%\FileManagerMulti\v1\engine，
    用私有 Everything.ini 运行：便携模式（app_data=0，不碰用户自己的
    %APPDATA%\Everything）、隐形（show_tray_icon=0）、关闭 HTTP / ETP
    服务与更新检查，避免和系统里已有的 Everything 抢端口抢配置。
  · 三级搜索来源，优先级明确：用户自己装过 Everything → 直接复用（绝不
    改它的配置）；没装 → 启动随包内核；内核也没法用 → 本地索引兜底。
    界面状态栏实时显示当前后端（内置引擎 / Everything SDK / 本地索引）。
  · 「启用全盘秒搜」一键授权：NTFS 的 MFT / USN 读取必须是管理员权限，
    Everything 的标准解法是装一个约 1MB 的常驻索引服务。点一次授权后
    永久静默、随系统启动，之后完全不再弹 UAC。设置里可查看内核来源、
    服务状态、内核版本，并可手动停止内核。
  · 内核进程跟随管理器：退出管理器时只结束「我们自己启动的」那个内核，
    用户自己开的 Everything 不受影响；索引靠 USN 日志增量维护，下次启动
    重读 MFT 一般 1–3 秒。
  · 卸载安全：只有当索引服务确实指向内置内核目录（说明是我们装的）时，
    才在卸载时一并移除，用户自己安装的 Everything 服务一律不动。

修复
  · 重要：Everything SDK 直连长期不可用（此前的版本实际一直在用本地索引）。
    原因是绑定了一个并不存在的导出函数 Everything_IsDirResult，connect()
    抛 AttributeError 被 available() 静默吞掉，于是「Everything SDK」这块
    永远返回不可用。现改为按可用性绑定（IsDirResult → IsFolderResult →
    GetResultAttributes 依次降级），单文件搜索从秒级降到几十毫秒。
  · 文件夹内搜索此前也一并退化成 os.walk 现场扫描（大目录要等十几秒）。
    现在 SDK 恢复可用后，folder 作用域同样走索引（path:"…" 限定），
    结果侧再做一次前缀校验，保证不会串到别的目录。
  · 内核启动期会卡住搜索：Everything 客户端刚启动时 IPC 窗口已注册但还
    没开始处理消息，此时同步 Everything_QueryW 会一直等（实测单次卡 23 秒，
    界面上就是「搜索中…」一直不动）。现在探测前先用
    FindWindowW(EVERYTHING_TASKBAR_NOTIFICATION) 判断实例是否存在，
    再用独立线程 + join(timeout) 兜住「有窗口但不响应」；search() 同样带
    6 秒上限，超时给出原因并退回本地索引，内核再卡也不会拖死搜索线程。
  · 退出时不再误关用户的 Everything：复用外部实例时也记了进程句柄，
    此前 stop() 会连它一起 terminate；现在只有「我们自己启动的内核」
    才会被结束。

变更
  · 状态栏后端名区分「内置引擎」与「Everything SDK」；未启用内置引擎时
    显示「本地索引 · 点此启用全盘秒搜」，点击直接进入引擎管理弹窗。
  · 打包体积增加约 2.3MB（内核），换来免安装 Everything。
